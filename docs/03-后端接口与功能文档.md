# 造物工坊 · 后端接口与功能文档

> 版本：v1.0（2026-11-27）
> 前端：Vue 3 + TypeScript + Vite + Pinia
> 适用对象：后端、联调、测试、产品
> 对应代码：`src/api/*`、`src/services/*`、`src/types/*`

---

## 1. 这份文档解决什么问题

前端目前是一个可直接运行的展示站：

- 商品、社区内容使用本地 mock 数据；
- 定制服务（上传参考图 → 建模 → 下单）已经有完整交互，默认走前端 mock；
- HTTP 层、接口模块、建模任务轮询、错误处理已经按本文档的契约实现。

后端按本文档实现后，把 `.env.development` 的 `VITE_USE_MOCK` 改成 `false`，再把商品/社区的数据入口从 `src/services/*` 切到 `src/api/*`，即可联调，页面组件不需要改。

## 2. 产品功能全景

### 2.1 页面与模块

| 页面 | 路由 | 功能 | 数据来源 |
| --- | --- | --- | --- |
| 首页 | `/` | 首屏作品轮播、四步流程、四种建模方式、社区精选、商城精选 | 静态内容 + 商品/社区服务 |
| 产品商城 | `/store` | 分类、现货/限量、价格带筛选；推荐/价格/热度排序；网格/列表切换；加购 | 商品服务 |
| 作品详情 | `/store/:id` | 图片/3D 切换、规格信息、数量选择、加购、相关推荐 | 商品服务 |
| 定制服务 | `/custom` | 上传 1–6 张参考图、上传进度、建模任务进度、3D 预览、填写收货资料、提交定制订单 | 上传 / 建模 / 订单接口 |
| 社区画廊 | `/community` | 分类筛选、作品瀑布流 | 社区服务 |

### 2.2 定制主流程（后端最需要关注）

```
选择参考图
  → POST /uploads/references（逐张上传，拿到 referenceId）
  → POST /custom/model-tasks（首张图上传完成后创建任务）
  → GET /custom/model-tasks/{taskId}（前端 1.1s 轮询，展示 progress）
  → succeeded：返回 modelUrl，前端用 Three.js 加载 .glb
  → 用户填写联系人 / 手机号 / 地址 / 备注
  → POST /custom/orders（携带 referenceIds）
  → 返回 orderNo，展示“我们已收到你的需求”
```

关键约束：

- 建模失败不影响下单，用户可以带着参考图和需求直接提交，由人工介入；
- 参考图是强个人隐私数据，后端必须按第 13 节处理；
- 建模是异步任务，不要让创建接口同步等待建模完成。

## 3. 通用约定

### 3.1 基础地址

- 前端读取 `VITE_API_BASE_URL`，默认 `/api`。
- 下文路径均相对于该前缀，例如 `GET /api/products`。
- 生产环境建议同域反向代理，避免额外 CORS 与 Cookie 问题。

### 3.2 协议与编码

- HTTPS（生产必须）。
- `Content-Type: application/json; charset=utf-8`；上传接口为 `multipart/form-data`。
- 时间统一 ISO 8601，带时区，例如 `2026-11-27T10:30:00+08:00`。
- 金额字段 `price` 单位为**元**，允许最多两位小数（前端按元展示）。如果后端内部用分存储，请在响应前换算。

### 3.3 鉴权

- 需要登录的接口使用 `Authorization: Bearer <token>`。
- 前端从 `localStorage` 的 `token` 读取并自动挂载。
- 商品、社区、上传、建模、定制下单当前允许匿名访问；如果后端要绑定会话，请使用 HttpOnly Cookie 或匿名 `sessionId`，不要让前端把用户 ID 放在请求体里。
- 401 时前端会清除本地 token 并提示“登录状态已失效”。

### 3.4 统一响应包

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "b7c2f0d1e8a94f6c"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | number | 是 | 0 表示成功，其他见 3.6 |
| message | string | 是 | 面向用户的错误文案；成功时可为 `ok` |
| data | any | 是 | 业务数据；无数据时返回 `null` |
| traceId | string | 否 | 链路追踪 ID，前端会透传到错误对象，便于排查 |

前端兼容两种返回：统一响应包，或直接返回裸数据。**新接口请统一使用响应包。**

### 3.5 分页

请求：

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| page | number | 1 | 从 1 开始 |
| pageSize | number | 20 | 最大 100 |

响应 `data`：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

### 3.6 业务错误码

| code | HTTP | 含义 | 前端处理 |
| --- | --- | --- | --- |
| 0 | 200/201/202 | 成功 | 正常取 `data` |
| 40000 | 400 | 参数错误 | 弹出 message |
| 40100 | 401 | 未登录 / 登录失效 | 清除 token，提示重新登录 |
| 40300 | 403 | 无权限 | 弹出 message |
| 40400 | 404 | 资源不存在 | 详情页展示空状态 |
| 41300 | 413 | 文件过大 | 提示压缩后重试 |
| 41500 | 415 | 文件格式不支持 | 提示仅支持 JPG/PNG/WebP |
| 42900 | 429 | 触发限流 | 提示稍后再试 |
| 50000 | 500 | 服务端异常 | 通用错误提示 |
| 51001 | 200 | 建模任务失败（业务失败） | 展示失败原因，可重试 |

> HTTP 状态码与业务 code 同时返回；前端以响应包里的 `code` 为准，HTTP 非 2xx 时读取 body 里的 `message`。

### 3.7 幂等

- `POST /custom/orders`、`POST /custom/model-tasks` 建议支持 `Idempotency-Key` 请求头。
- 同一个 key 在 24 小时内重复提交，返回第一次的结果，避免用户重复点击/网络重试造成重复订单或重复计费。
- 前端当前未强制发送该头；后端可先做“同手机号 + 同参考图 + 5 分钟内”去重兜底。

### 3.8 字段命名

- JSON 使用 `camelCase`。
- 枚举使用英文常量，前端已有对应中文展示，不要在接口里返回中文枚举。

## 4. 商品接口

### 4.1 商品列表 `GET /products`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| category | string | 否 | `潮流潮玩` / `珍藏纪念` / `创意礼物` / `装饰美学`；不传为全部 |
| availability | string | 否 | `all` / `in-stock` / `limited` |
| priceBand | string | 否 | `all` / `under-500` / `500-1000` / `over-1000` |
| sort | string | 否 | `recommended` / `price-asc` / `price-desc` / `popular` |
| keyword | string | 否 | 标题模糊搜索 |
| page | number | 否 | 默认 1 |
| pageSize | number | 否 | 默认 20 |

`availability` 语义（与当前前端一致）：

- `in-stock`：开放版，可现货购买（没有 `limited` 标记）；
- `limited`：限量版；
- 后端如果引入真实库存，请新增 `stockStatus` 字段，前端再适配，避免用 badge 代替库存。

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "clay-guard",
        "title": "黏土门神",
        "price": 268,
        "sold": 1284,
        "category": "珍藏纪念",
        "badge": "limited",
        "edition": "限量 300 版",
        "ratio": "4:5",
        "image": "https://cdn.example.com/products/clay-guard.webp",
        "model": "https://cdn.example.com/models/clay-guard.glb"
      }
    ],
    "total": 16,
    "page": 1,
    "pageSize": 20
  }
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 稳定 ID，用于详情、购物车持久化 |
| title | string | 是 | 商品名 |
| price | number | 是 | 单位元，最多两位小数 |
| sold | number | 是 | 已售数量，用于“热度”排序 |
| category | string | 是 | 四类之一 |
| badge | string | 否 | `fan`（粉丝共创）/ `limited`（限量） |
| edition | string | 是 | 版数说明，例如“限量 300 版” |
| ratio | string | 是 | 展示比例：`1:1` / `4:5` / `3:4` / `5:4` |
| image | string | 是 | 主图；建议 WebP，至少 1200px 宽 |
| model | string | 否 | `.glb` 地址；没有则前端展示内置占位浮雕 |

## 6. 参考图上传 `POST /uploads/references`

### 6.1 请求

`multipart/form-data`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | binary | 是 | 单张图片 |
| scene | string | 否 | 固定 `custom`，便于后端做策略 |

约束（前端已校验，后端必须再校验）：

- 格式：JPEG / PNG / WebP；
- 大小：≤ 10MB / 张；
- 数量：单个定制单最多 6 张；
- 建议最短边 ≥ 1024px，低于 800px 时建模质量会明显下降；
- 文件名只用于展示，不要拼进存储路径。

### 6.2 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "ref_01J8Z9K3M4",
    "url": "https://cdn.example.com/private/ref_01J8Z9K3M4.webp"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| id | 文件 ID，后续建模任务与订单都用它 |
| url | 可访问地址；私有桶请返回带有效期的签名 URL |

错误：

- 413：`41300`，文案“图片超过 10MB”；
- 415：`41500`，文案“仅支持 JPG / PNG / WebP”；
- 429：`42900`，单 IP / 单会话每分钟最多 10 次上传。

### 6.3 存储与隐私要求

- 参考图属于用户个人照片，必须放**私有桶**，禁止公开 CDN 目录；
- 上传后剥离 EXIF（尤其是 GPS、设备信息），统一转 WebP/JPEG 并限制最大边 4096px；
- 存储路径使用随机 UUID，不使用原始文件名；
- 记录 `createdAt / expiresAt / ownerSession / deletedAt`；
- 默认保留 30 天；订单完成后用户可申请删除；
- 未经用户明确授权，不得用于社区展示、模型训练或对外宣传；
- 建议接入图片安全扫描（涉黄/涉暴/违法内容），命中直接拒绝并记录审计日志。

## 7. 建模任务

### 7.1 创建任务 `POST /custom/model-tasks`

请求：

```json
{
  "productId": "clay-guard",
  "referenceIds": ["ref_01J8Z9K3M4"],
  "note": "保留耳朵和项圈"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| productId | string | 否 | 从某个商品详情进入定制时携带 |
| referenceIds | string[] | 是 | 1–6 个已上传文件 ID；第一张为主参考图 |
| note | string | 否 | 用户补充要求，≤ 200 字 |

响应 `202 Accepted`：

```json
{
  "code": 0,
  "message": "accepted",
  "data": {
    "taskId": "mt_01J8ZBN7Q2",
    "status": "queued",
    "progress": 0
  }
}
```

校验：

- `referenceIds` 必须存在、未过期、未被删除；
- 建议校验文件归属（会话或匿名 session），防止枚举他人图片；
- 同一 `Idempotency-Key` 重复请求返回同一 taskId。

错误：

- 40400：参考图不存在/已过期；
- 42900：单会话同时最多 2 个建模任务。

### 7.2 查询任务 `GET /custom/model-tasks/{taskId}`

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "taskId": "mt_01J8ZBN7Q2",
    "status": "processing",
    "progress": 68,
    "modelUrl": null,
    "previewUrl": null,
    "errorMessage": null
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| taskId | string | 任务 ID |
| status | string | `queued` / `processing` / `succeeded` / `failed` |
| progress | number | 0–100 整数，**单调不减**；`succeeded` 时必须为 100 |
| modelUrl | string \| null | 成功后的 `.glb` 地址 |
| previewUrl | string \| null | 成功后的预览图，前端可优先展示 |
| errorMessage | string \| null | 失败原因，直接展示给用户 |

状态机：

```
queued ──→ processing ──→ succeeded
   │            │
   └────────────┴──→ failed
```

约定：

- 前端每 1.1 秒轮询一次；建议后端对同一 task 的查询做 1 秒缓存；
- 超过 10 分钟仍未结束，前端判定超时并允许重试；后端应在 8 分钟内主动置为 `failed`（`errorMessage="建模超时，请重试"`）；
- `failed` 时 HTTP 仍返回 200，`code=0`，通过 `status` 表达业务失败；如果整体接口失败才用 `51001`；
- 成功后 `modelUrl` 必须可跨域访问；如果是签名 URL，有效期至少 7 天。

### 7.3 模型文件要求

- 格式：`.glb`（glTF 2.0 二进制），允许 Draco 压缩；
- 大小：建议 ≤ 50MB；
- 纹理：尽量内嵌，避免外链纹理的 CORS 问题；
- 坐标：Y 轴向上，模型居中；前端会根据包围盒自动取景，不强制单位；
- 背景透明，不要烘焙环境光；
- 失败降级：没有 `modelUrl` 时前端回退到本地照片浮雕预览，不会阻塞下单。

### 7.4 取消任务 `DELETE /custom/model-tasks/{taskId}`

- 成功返回 `204 No Content`；
- 幂等：任务已完成或不存在也返回 204；
- 用于前端移除参考图、离开页面时释放算力。前端会静默处理失败。

## 8. 定制订单 `POST /custom/orders`

### 8.1 请求

```json
{
  "productId": "clay-guard",
  "referenceIds": ["ref_01J8Z9K3M4", "ref_01J8Z9K3M5"],
  "note": "尺寸 20cm，保留胡须",
  "customer": {
    "name": "吴先生",
    "phone": "13800138000",
    "address": "广东省东莞市松山湖园区示例路 1 号"
  }
}
```

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| productId | string | 否 | 关联商品；纯定制可为空 |
| referenceIds | string[] | 是 | 1–6 个，且都已上传成功 |
| note | string | 否 | ≤ 200 字 |
| customer.name | string | 是 | 1–20 字 |
| customer.phone | string | 是 | 中国大陆手机号 `^1[3-9]\d{9}$` |
| customer.address | string | 是 | 5–120 字 |

前端已做同样校验，后端仍需校验。

### 8.2 响应

```json
{
  "code": 0,
  "message": "created",
  "data": {
    "orderId": "ord_01J8ZCF3R7",
    "orderNo": "CW20261127001",
    "status": "pending"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| orderId | 内部 ID |
| orderNo | 对用户展示的订单号，建议可读、唯一 |
| status | `pending` / `confirmed` / `producing` / `shipped` / `completed` / `cancelled` |

订单状态建议：

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| pending | 待人工确认方案与报价 | 客服 1 个工作日内联系 |
| confirmed | 已确认方案、待付款/已付款 | 进入排产 |
| producing | 制作中 | 可展示进度 |
| shipped | 已发货 | 提供运单号 |
| completed | 已完成 | 可评价 |
| cancelled | 已取消 | 释放文件 |

### 8.3 错误

| 场景 | code | 文案 |
| --- | --- | --- |
| 参考图缺失/过期 | 40000 / 40400 | 参考图已过期，请重新上传 |
| 手机号格式错误 | 40000 | 手机号格式不正确 |
| 重复提交 | 200（返回原单） | 已收到你的需求 |
| 限流 | 42900 | 操作过于频繁 |

### 8.4 订单查询（预留）

`GET /orders/{orderNo}` 返回订单详情、状态、报价、物流。当前前端只展示下单成功态，没有订单中心；后续可加“我的订单”页。

## 10. 数据模型与枚举汇总

## 12. Mock 与联调

### 12.1 开关

`.env.development`：

```dotenv
VITE_API_BASE_URL=/api
VITE_USE_MOCK=true
```

- `VITE_USE_MOCK` 未设置为字符串 `false` 时都走 mock；
- 接后端时改为 `false`，重启 dev server。

Mock 行为：

| 能力 | Mock 行为 |
| --- | --- |
| 上传 | 约 0.7s 模拟进度，返回 `id=mock-ref-*`，`url=""` |
| 建模 | 约 2.4–3.6s 完成，`progress` 递增，`modelUrl` 为空 |
| 订单 | 约 0.7s 返回 `orderNo=CW{时间戳后 8 位}` |

因此 mock 下预览区展示的是**前端根据照片生成的浮雕**，不是后端模型；接真实建模后会自动切换为 `ModelViewer` 加载 `.glb`。

### 12.2 本地代理示例

`vite.config.ts` 可加：

```ts
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
    },
  },
}
```

### 12.3 联调检查顺序

1. `GET /products` 返回响应包，分页字段正确；
2. 上传 1 张 JPG，拿到 `id`；
3. 创建建模任务，轮询能看到 `queued → processing → succeeded`；
4. `modelUrl` 能被浏览器直接打开并加载；
5. 提交订单，拿到 `orderNo`；
6. 刷新页面，购物车仍存在（本地能力，不依赖后端）；
7. 401 / 413 / 415 / 429 各触发一次，确认提示文案。

## 13. 非功能与安全要求

### 13.1 性能

- 商品/社区列表 p95 ≤ 300ms（可加 Redis 缓存 + ETag）；
- 图片走 CDN，WebP，列表图 ≤ 300KB；
- 建模创建接口只落任务，立即返回，不要同步等待；
- 任务查询接口允许 1 秒缓存，避免轮询打爆数据库；
- 上传接口单张 10MB，建议分片或直传对象存储（前端当前是普通 multipart）。

### 13.2 稳定性

- 建模任务要有重试与死信队列；失败原因可读；
- 订单创建与文件绑定要在一个事务里完成；
- `traceId` 全链路透传，前端错误提示不暴露堆栈。

### 13.3 安全与隐私

- 参考图私有存储、签名 URL、EXIF 剥离、30 天保留、可删除；
- 上传做 MIME + 魔数双重校验，防止改扩展名；
- 图片安全扫描，命中违规直接拒绝；
- 订单接口限流：单 IP 10 次/分钟、单手机号 3 次/小时；
- 日志脱敏：手机号中间四位打码，地址只记录省市；
- 禁止把用户照片用于训练/展示，除非有单独授权文案与勾选；
- 管理后台访问需最小权限 + 审计日志；
- CORS 只允许正式域名与本地开发端口，不要 `*` 配合 credentials。

### 13.4 合规提示

定制照片可能包含人脸、未成年人、宠物等信息。上线前需要：

- 隐私政策明确“照片用途、保留期限、删除方式”；
- 下单页增加“授权用于制作，不用于公开展示”的勾选；
- 提供删除申请入口（可先人工客服）。

当前前端**没有**这个勾选框，建议后端上线前一起补。
