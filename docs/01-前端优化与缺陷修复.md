# 前端优化与缺陷修复记录

> 版本：v1.0（2026-11-27）
> 范围：`C:\Users\dong\Desktop\web` 全站（首页 / 商城 / 详情 / 定制 / 社区）
> 验证：`npm run build` 通过（vue-tsc + vite build）

---

## 1. 结论先说

这次做了三类事：

1. **修真实缺陷**：购物车刷新丢失、详情页切商品状态串台、图片换图卡占位、上传删除竞态、建模计时器泄漏、下单可带失败图片等 20 余处；
2. **组件化**：抽出 `QuantityStepper`、`SectionHead`、`CartDrawer`，重构 `ReferenceUploader` 的 v-model 契约，统一 3D 生命周期；
3. **接口化**：统一响应包/错误处理，新增 `api/catalog`、`api/community`、`api/custom` 与 `useModelingTask`，商品/社区数据改走 `services` 层。

体积变化：

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 主包 `index.js` | 1,044.62 KB（gzip 339.06 KB） | 239.00 KB（gzip 84.99 KB） |
| `ThreeStage` 3D 包 | 628.04 KB | 628.21 KB（按路由分包，未变） |
| Element Plus | 全量 `app.use(ElementPlus)` | 按需注册 9 个组件 |

主包体积下降约 **77%**，主要来自 Element Plus 不再全量引入。3D 包仍然是详情/定制页的主要体积，已在路由层分包。

## 2. 缺陷清单

严重度：P0 阻断/数据错误，P1 明显影响体验，P2 细节/可维护性。

### 2.1 购物车域

| 编号 | 级别 | 位置 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- | --- |
| B01 | P1 | `src/stores/cart.ts` | 加购后刷新页面，购物车清空；代码注释却写着“sessionStorage 持久化” | 注释与实现不符，实际没有任何持久化 | 改为 localStorage 持久化，只存 `{id, quantity}`；初始化按商品表还原，下架商品自动剔除 |
| B02 | P1 | `FloatingCart.vue` | 加购后点右下角购物车只弹“演示”提示，看不到商品，也无法改数量 | 没有购物车详情界面 | 新增 `CartDrawer`，支持数量、删除、合计、空态；FloatingCart 直接打开抽屉 |
| B03 | P2 | `stores/cart.ts` | 外部传入 `NaN` 或负数时数量异常；数量无上限 | `setQuantity` 未做归一化 | 新增 `normalizeQuantity`，统一 1–99 整数；`<=0` 自动移除；总价按分计算避免浮点误差 |
| B04 | P2 | `stores/cart.ts` | 商品价格变化后，购物车里仍是旧价 | 直接持久化整个 ProductItem | 只持久化 id + 数量，价格始终从商品表读取 |

### 2.2 商品详情 / 图片

| 编号 | 级别 | 位置 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- | --- |
| B05 | P0 | `ProductDetail.vue` | 从详情 A 点相关推荐进 B，购买数量还是 A 的数量；A 的 3D 加载失败后，B 也一直停留在图片模式 | Vue Router 复用同一组件实例，`quantity/show3d/viewerFailed` 没有随路由参数重置 | `watch(() => route.params.id)` 重置数量、3D 开关、失败态；浏览器标题同步更新 |
| B06 | P1 | `SmartImage.vue` | 同一个组件换 `src` 后，新图一直不显示，或加载失败后永远显示“图片不可用” | `loaded/failed` 只在挂载时初始化，换图不重置 | `watch(src)` 重置状态；空 `src` 不渲染 `<img>`，避免请求当前页面 |
| B07 | P2 | `utils/format.ts` | 后端如果返回 `268.50`，页面显示 `¥269` | `maximumFractionDigits: 0` | 改为最多两位小数；非法值显示 `¥--` |
| B08 | P2 | `ProductDetail.vue` | 详情页切换商品后浏览器标题仍是“作品详情” | 只有路由 `meta.title` 静态标题 | `watchEffect` 按商品名更新标题 |

### 2.3 3D 渲染

| 编号 | 级别 | 位置 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- | --- |
| B09 | P1 | `ModelViewer.vue` | 注释说“同 URL 只下载一次”，但离开详情再回来仍重复下载；多个实例各存一份 | 缓存放按组件实例内，实例销毁缓存即丢 | 缓存提升到模块级，跨实例共享；LRU 3 个 + 96MB 上限 |
| B10 | P1 | `ModelViewer.vue` | 快速切页时，旧的 GLB 加载完成后仍往已卸载的舞台挂模型；控制台出现 undefined 访问 | 异步加载没有取消/失效判断 | `loadToken + disposed` 双重校验；切模型前 `clearObject()`；卸载时 token 失效 |
| B11 | P1 | `ModelViewer.vue` | 断网/内网环境下 Draco 模型加载失败 | `setDecoderPath('https://www.gstatic.com/...')` 依赖外网 | three 新版 DRACOLoader 已内置随包解码器，移除外链，离线可用 |
| B12 | P1 | `ThreeStage.vue` | 3D 区块滚出视口后，切回浏览器标签页又会开始渲染；滚动回来反而可能不渲染 | `visibilitychange` 与 `IntersectionObserver` 各自 start/stop，两个信号互相覆盖 | 用 `onScreen + document.hidden` 合成 `syncLoop()`，只有一个判断入口 |
| B13 | P2 | `ThreeStage.vue` | 动态修改 `exposure` / `fitPadding` 不生效 | 只在初始化时读取 props | 增加两个 `watch`，实时更新曝光与取景 |
| B14 | P2 | `ReliefPreview.vue` | 舞台未就绪时挂载失败，geometry/material/texture 泄漏 | 失败分支只抛错，没有释放刚创建的对象 | 新增 `disposeRelief()`；每次重建前 `clearObject()` |

### 2.4 上传 / 定制

| 编号 | 级别 | 位置 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- | --- |
| B15 | P0 | `ReferenceUploader.vue` | `v-model` 只输出 `File[]`，父级拿不到上传状态和文件 ID；外部清空时组件内部不跟着清空 | 组件是“单向输出”，不是受控组件 | 改为 `v-model: ReferenceFile[]`，含 `uid/status/progress/referenceId`；`watch(modelValue)` 支持外部重置/初始化；emit 快照并防回灌 |
| B16 | P1 | `ReferenceUploader.vue` | 上传中删除图片，上传完成后状态写回已删除条目，列表出现“幽灵项” | 删除时没有取消/校验异步结果 | 上传回调每次检查 `items.includes(item)`，已删除直接丢弃；移除时同步 emit |
| B17 | P1 | `ReferenceUploader.vue` | 大量上传/删除后内存上涨 | 本地预览 ObjectURL 只在卸载时回收；mock 上传还额外创建了一个 ObjectURL | 删除、清空、卸载三处回收；mock 上传不再创建 blob URL |
| B18 | P0 | `CustomOrderView.vue` | 参考图还在上传、或上传失败时也能点“生成定制方案”，订单里带的是本地 File，后端拿不到文件 | 只校验 `files.length > 0` | 新增 `canSubmit`：至少 1 张 `done` 且带 `referenceId`，且无 `uploading/error`；上传中按钮显示“上传中…” |
| B19 | P1 | `CustomOrderView.vue` | 建模动画用 `setInterval` 模拟，离开页面/移除图片后计时器仍在跑；无法重试、无法取消 | 页面内自建计时器，没有任务抽象 | 新增 `useModelingTask`：创建任务 → 轮询 → 成功/失败/取消/超时；卸载自动取消；真实接口可切换 |
| B20 | P1 | `api/custom.ts` | mock 上传返回 `URL.createObjectURL(file)`，永不回收；订单提交把 File 数组塞进 JSON（真实接口会变成 `{}`） | mock 与真实契约不一致 | mock 返回 `{id,url:''}`；订单只提交 `referenceIds`，与后端文档一致 |
| B21 | P2 | `CustomOrderView.vue` | 下单成功只显示 `orderId`，没有对用户更友好的订单号；关闭后参考图与表单未清理 | 只存了 orderId；`handleClosed` 依赖 orderId | 同时保存 `orderNo` 展示；关闭成功态后重置表单、参考图、建模任务 |
| B22 | P2 | `CustomOrderView.vue` | 每次进定制页都强制弹“上传提示”，重复打扰 | `guideVisible` 固定 `true` | 用 localStorage 记住已读；卡片头增加“上传说明”入口，可主动重看 |

## 3. 优化项（非缺陷）

| 项 | 说明 |
| --- | --- |
| 路由懒加载 | 5 个页面全部 `() => import()`，`ThreeStage` 单独分包 |
| 重组件异步 | `ModelViewer` 用 `defineAsyncComponent`，没有 3D 结果时不加载 GLTFLoader |
| 图片规范 | `SmartImage` 统一 lazy/async/占位/失败态 |
| 组件文档 | `docs/02-前端组件规范.md` 明确契约、生命周期、检查清单 |
| 接口文档 | `docs/03-后端接口与功能文档.md` 给出完整 endpoint、字段、状态机、安全要求 |
| mock 开关 | `VITE_USE_MOCK` 环境变量，接后端不用改代码 |
| 错误可观测 | 后端可回传 `traceId`，前端错误对象保留 code/status/traceId |
