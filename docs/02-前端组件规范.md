# 前端组件规范与维护手册

> 版本：v1.0（2026-11-27）
> 目标：让组件可复用、可替换、可测试，新增页面时不用复制粘贴一大段模板。

---

## 1. 目录分层

```
src/
├─ api/                 # HTTP 接口：只负责路径、参数、响应类型
│  ├─ request.ts        # axios 实例、响应包解包、错误提示、token
│  ├─ catalog.ts        # 商品接口
│  ├─ community.ts      # 社区接口
│  └─ custom.ts         # 上传 / 建模任务 / 定制订单
├─ services/            # 数据入口：页面组件只依赖这一层
│  ├─ catalog.ts
│  ├─ community.ts
│  └─ content.ts
├─ data/                # mock 数据库，仅 service 层可以 import
├─ types/               # 领域类型：商品、社区、上传、接口、购物车、内容
├─ composables/         # 跨组件逻辑：筛选、入场动画、建模轮询
├─ stores/              # Pinia：购物车
├─ components/
│  ├─ common/           # 与业务无关的基础组件
│  ├─ cart/             # 购物车抽屉
│  ├─ custom/           # 定制业务组件
│  ├─ home/             # 首页区块
│  ├─ store/            # 商城组件
│  ├─ community/        # 社区组件
│  └─ layout/           # 顶栏、页脚
├─ views/               # 页面：只做编排，不写复杂 DOM 逻辑
├─ plugins/             # Element Plus 按需注册
└─ utils/               # 纯函数与安全存储
```

依赖方向（只允许向下）：

```
views → components → composables / stores / services → api / data
```

硬规则：

1. **组件不直接 import `@/data/*`**。要数据找 `services`，要类型找 `types`。
2. **api 层不 import 组件**，也不弹业务弹窗（错误提示统一在拦截器）。
3. **基础组件不依赖业务 Store**。`QuantityStepper` 不知道购物车存在，只发事件。
4. **页面组件不写 `fetch`**，请求交给 api/service。
5. 跨页面共享的状态放 Pinia，组件内部状态用 `ref`，不要用模块级可变变量（3D 缓存除外，见 4.3）。

## 2. 组件契约

### 2.1 语法与类型

- 一律 `<script setup lang="ts">`。
- props 用 `defineProps<{...}>()`，默认值用 `withDefaults`。
- emits 用 `defineEmits<{ (e: 'xxx', payload: T): void }>()`，不要字符串数组。
- 对外暴露的方法用 `defineExpose`，并在注释里写清用途。
- 不使用 `any`；第三方对象用 `InstanceType<typeof X>` 或明确的接口。

### 2.2 v-model

受控组件必须满足：

- 有 `modelValue` prop；
- 变更时只 `emit('update:modelValue', next)`，**不直接改 prop**；
- 内部需要缓存时，用 `watch(() => props.modelValue)` 同步，并防止 emit 回灌造成循环。

示例：`QuantityStepper`、`ReferenceUploader`、`TextSelect`。

### 2.3 插槽

- 标题右侧操作、卡片底部操作、空状态按钮，优先用命名插槽，不要把业务按钮写进通用组件。
- `SectionHead` 的 `#actions` 是标准示例。

### 2.4 事件命名

- 变更：`update:modelValue`
- 用户动作：`add` / `select` / `remove` / `retry`
- 生命周期：`ready` / `error`
- 不要用 `click` 作为业务事件名，避免和原生事件混淆。

### 2.5 样式

- 组件样式 `scoped`；需要穿透 Element Plus 时用 `:deep()` 或 `:global()`。
- 颜色、圆角、间距优先用 `src/style.css` 里的 CSS 变量（`--text-primary`、`--hairline`、`--radius-pill` 等）。
- 类名用 BEM 风格：`.product-tile__media`、`.cart-item__price`。
- 不引入新的 UI 框架；Element Plus 只用于弹窗、表单、图标、Popover、Badge、Drawer。

## 4. 生命周期与资源管理

### 4.1 定时器 / 轮询 / 观察器

- `setInterval` / `setTimeout` 必须保存句柄，在 `onBeforeUnmount` 清理。
- 建模轮询统一用 `useModelingTask`，不要页面里再写一套。
- `IntersectionObserver` / `ResizeObserver` / `MutationObserver` 必须在卸载时 `disconnect()`。
- 异步请求必须带 token（递增的 `loadToken` 或 `requestToken`），回调前检查：
  “组件是否已卸载？token 是否还是最新一次？”

### 4.2 ObjectURL

- 组件创建的 `URL.createObjectURL(file)` 由创建者回收；
- 删除条目、清空、组件卸载三处都要 `revokeObjectURL`；
- 父组件如果也要用预览图，自己创建一个独立的 ObjectURL，不要和子组件共用同一个再互相 revoke。

### 4.3 three.js

`ThreeStage` 的约定：

1. 业务组件准备好 `Object3D` 后调用 `setObject(object)`；
2. `setObject` 会自动 dispose 上一个对象（geometry / material / texture）；
3. 业务组件切换模型前可调用 `clearObject()`；
4. 舞台卸载时会 `renderer.dispose()` + `forceContextLoss()`；
5. 只有“在视口内 + 页面可见”才渲染，两个条件用 `syncLoop()` 统一判断，不要各自 `start/stop`。

`ModelViewer` 的约定：

1. GLB 二进制缓存在模块级，跨实例共享；
2. 缓存同时限制条数（3）和总字节（96MB），淘汰最旧；
3. fetch / parse 全过程带 `loadToken`，卸载或切模型后丢弃结果；
4. 解析失败 / 非 GLB 时展示占位模型并 `emit('error')`；
5. three 的 Draco 解码器已随包内置，不要改回 gstatic 外链。

### 4.4 图片

`SmartImage` 已处理：

- 加载中占位；
- 失败占位；
- `src` 变化时重置 `loaded/failed`；
- 空 `src` 不渲染 `<img>`，避免请求当前页面 URL。

## 5. 数据与状态

### 5.1 商品 / 社区

- 页面和组件从 `services/catalog.ts`、`services/community.ts` 取数据；
- 目前 service 返回同步 mock。接后端时改 service 内部实现，组件不需要动；
- 如果改成异步，需要在页面增加 loading 骨架，建议用 Pinia `catalogStore.ensureLoaded()` 统一管理，避免每个卡片各自请求。

### 5.2 购物车

`stores/cart.ts` 是唯一状态源：

- `items` 只存 `{ product, quantity }`；
- 持久化只写 `{ id, quantity }`，价格永远取商品表；
- 商品下架后，刷新时自动剔除；
- 数量统一走 `normalizeQuantity`（1–99，整数）；
- 抽屉开关 `drawerOpen` 也在 store，`FloatingCart` 和 `CartDrawer` 共享。

### 5.3 建模任务

`composables/useModelingTask.ts`：

- `start(payload)`：创建任务，进入 `queued`，开始轮询；
- 轮询间隔 1.1s，最长 10 分钟；
- `progress` 单调，失败有 `errorMessage`；
- `cancel()`：停止轮询 + 通知后端删除任务；
- 组件卸载自动取消；
- 页面只消费 `phase / progress / modelUrl / errorMessage / isBusy`。

注意：从 composable 返回的对象里的 `ref` 在模板中**不会自动解包**。页面要解构：

```ts
const { phase, progress, isBusy, modelUrl, retry } = useModelingTask()
```

## 6. 无障碍与交互

- 所有图标按钮必须有 `aria-label` 或可见文字；
- 可点击的 `div` 改成 `button`，或补 `role/tabindex/keydown`；
- 焦点可见：不要全局 `outline: none`；
- 下拉、Tab 支持 `ArrowUp/Down`、`Home/End`、`Esc`；
- 动效尊重 `prefers-reduced-motion`（入场动画已处理）；
- 弹窗打开后焦点进入弹窗，关闭后回到触发按钮（Element Plus 已处理大部分）。

---

## 7. 性能约定

1. 路由级懒加载：`views` 全部 `() => import()`。
2. 重组件异步：`ModelViewer` 用 `defineAsyncComponent`。
3. 3D 单独分包：`ThreeStage` 约 628KB，只在详情/定制页加载。
4. Element Plus **按需注册**（`src/plugins/element-plus.ts`）。新增 `el-xxx` 必须在这里补一行，否则运行时报“未注册组件”。
5. 图片 `loading="lazy"`、`decoding="async"`。
6. 列表筛选在客户端完成（当前数据量小）；数据量变大后改后端分页。
7. 不在模板里写复杂表达式；计算放 `computed`。

## 8. 新增组件 / 页面的检查清单

### 新增一个展示组件

- [ ] 放在合适的 `components/` 子目录；
- [ ] props / emits 有类型；
- [ ] 不直接 import `data`、不直接发请求；
- [ ] 文案可配置（不要写死在模板里）；
- [ ] 有空态 / 加载态 / 失败态（如适用）；
- [ ] 键盘可操作、图标有 `aria-label`；
- [ ] 样式 scoped，使用设计变量。

### 新增一个页面

- [ ] 在 `router/index.ts` 增加路由 + `meta.title`；
- [ ] 页面只编排组件，业务逻辑进 composable/store；
- [ ] 首屏有 loading / 空态；
- [ ] 接入 api 时用 `src/api`，不要在页面写 axios；
- [ ] 移动端 360px 宽度检查；
- [ ] `npm run build` 通过。

### 新增一个接口

- [ ] 在 `types/api.ts` 或对应领域类型里定义请求/响应；
- [ ] 在 `src/api/*.ts` 增加函数；
- [ ] 在 `src/services/*` 暴露给页面（或页面直接调用 api，视场景）；
- [ ] mock 分支与真实分支返回结构一致；
- [ ] 在 `docs/03-后端接口与功能文档.md` 补接口说明；
- [ ] 错误提示交给拦截器，页面只处理业务态。

### 新增一个 3D 模型

- [ ] 放到 `public/models/`，或上传 CDN；
- [ ] 在商品数据里填 `model: '/models/xxx.glb'`；
- [ ] 确认 `.glb` 可访问、无外链纹理、CORS 正常；
- [ ] 没有模型时保留占位浮雕，不要空白。

## 9. 已知限制

1. 商品/社区仍读本地 mock，service 是同步函数；接后端需要一次异步化改造。
2. `ThreeStage` 打包后约 628KB（gzip 157KB），已做路由分包，但仍是详情/定制页的主要体积。
3. Element Plus 仍引入完整 CSS（约 382KB / gzip 52KB），后续可按组件引样式进一步压缩。
4. 购物车“去结算”是演示提示，支付与商品订单接口未接。
5. 定制下单没有图片授权勾选，上线前需补合规文案。
6. 没有自动化测试；当前靠 `vue-tsc` + 手工回归。建议后续加 Vitest + Playwright。
